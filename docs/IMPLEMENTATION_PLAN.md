# 実装計画

## 現在の実装（Phase 3進行中）

- NeoForge 26.2 / Java 25 / ModDevGradleの公式構成
- `#minecraft:village` による2村の検出
- Countered's Settlement Roadsを基にした地形対応A*経路探索
- 道幅の展開と、サーバーティック単位の道路敷設
- 水面の簡易木橋と、自然物の最小限の除去
- 村中心付近を保護する敷設余白
- プレビュー、座標指定接続、周辺2村の接続コマンド
- 発見済み村・接続済みペア・生成途中キューの `SavedData` 永続化
- サーバー再起動後の生成再開と、接続方向に依存しない重複防止
- 保存済み村に対する最小全域木の道路ネットワーク計画
- 保存接続の一覧表示、生成待ちの解除、再生成準備コマンド
- 読み込まれた新規・既存チャンク内の村構造物の自動発見
- 未接続の最寄り村に対する自動道路計画
- A*探索を設定可能な地点数ずつ進めるティック分割処理
- 経路探索の単体テストとGitHub Actionsによるビルド検証

## Phase 2: 保存と道路ネットワーク

1. ✅ 発見済みの村をワールドの `SavedData` に保存する。
2. ✅ 接続済みの村ペアを正規化し、同じ道路を重複生成しないようにする。
3. ✅ 敷設途中のキューを保存し、再起動後に再開する。
4. ✅ 複数の村に対して、最小全域木を基準に接続候補を選ぶ。
5. ✅ 接続の一覧表示と、生成待ちを含む保存記録の解除を管理コマンドとして追加する。

完了条件: 再起動を挟んでも道路ネットワークと生成処理が壊れないこと。

## Phase 3: 自動発見と生成

1. ✅ 新しい村の構造物が生成・読み込みされたことを安全に検出する。
2. ✅ 自動生成を設定で明示的に有効化できるようにする。
3. ✅ 経路探索自体を複数ティックに分割し、長距離探索時の停止時間を抑える。
4. 未生成チャンクの扱いとチャンクチケットの寿命を定義する。
5. ✅ 既存ワールドでは、実際に読み込まれたチャンクだけを順次走査する。

完了条件: 管理コマンドなしでも新しい村同士が重複なく接続されること。

## Phase 4: 道路品質と装飾

- バイオーム別の道路素材をデータ駆動にする。
- 階段・ハーフブロックによる急斜面の整形を追加する。
- 川幅に応じた橋と橋脚を追加する。
- 元MODの街灯、標識、ウェイポイントを段階的に移植する。
- 大規模地形生成MODとの互換性を検証する。
- GameTestと実ワールドの回帰テストを追加する。

## 設計上の境界

- `road` パッケージにはMinecraft API非依存の経路ロジックを置く。
- `world` パッケージに村検出、地形サンプリング、ブロック変更を閉じ込める。
- ワールド変更は経路計画と分離し、プレビューしてから実行できるようにする。
- Minecraftのワールドへはサーバースレッドからだけアクセスする。
- 自動生成は保存・重複防止・復旧の実装後に有効化する。
