# 実装計画

## 現在の土台（Phase 0）

- NeoForge 26.2 / Java 25 / ModDevGradleの公式構成
- サーバー・クライアントの両方で読み込める最小MOD
- 最大接続距離、道路幅、1ティック当たりの処理上限を共通設定として定義
- Minecraft API非依存の直線道路プランナーと単体テスト
- `/muramusubi status` と `/muramusubi plan` による動作確認
- GitHub Actionsによるビルド検証

## Phase 1: 村の検出と道路ネットワーク計画

1. サーバー上で村の構造物またはPOIを検出する。
2. 検出結果を村ノードとして正規化し、重複を除去する。
3. 最大接続距離内の候補辺を作る。
4. 最小全域木を基準に、道路が過密にならない接続を選ぶ。
5. 道路ネットワークをワールドの保存データに記録する。

完了条件: 管理コマンドで周辺の村と接続候補を一覧・可視化できること。ブロックはまだ置かない。

## Phase 2: 地形対応の経路探索

1. 高さ、斜面、水、危険な地形をコストに変換する。
2. チャンクを強制生成しない範囲で粗いA*探索を行う。
3. 得られた経路を平滑化し、道路幅を展開する。
4. 探索を処理予算で分割し、サーバーティックを塞がないようにする。

完了条件: 既に読み込まれた地形上で道路候補を安全に計算できること。

## Phase 3: 道路の生成と復旧

1. 設定した処理上限の範囲で道路ブロックを設置する。
2. 地形に合わせて土台、階段、ハーフブロックを選ぶ。
3. 小規模な水場に簡易橋を生成する。
4. 中断した生成キューを保存し、再起動後に再開する。
5. バックアップを促す明示的な有効化設定と管理コマンドを用意する。

完了条件: 専用サーバーで再起動を挟んでも、道路生成が重複・破損せず完了すること。

## Phase 4: 自動生成と互換性

- 新しい村の発見時に道路計画を更新する。
- バイオーム別素材、道路標識、橋デザインをデータ駆動にする。
- 大規模な地形生成MODとの互換性を検証する。
- 設定移行、GameTest、リリース用メタデータを整備する。

## 設計上の境界

- `road` パッケージには経路・ネットワークの純粋ロジックを置く。
- Minecraft/NeoForge APIへの依存は検出、保存、コマンド、ブロック設置の境界へ閉じ込める。
- ワールド変更は計画と分離し、プレビューしてから実行できるようにする。
- 未生成チャンクを暗黙に生成しない。
